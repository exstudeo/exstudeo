# Exstudeo Developer Reference

## Vision

**Exstudeo** is a reader/viewer for notes and books in various formats — Markdown, EPUB, and more. The frontend is a Progressive Web App (PWA) enabling offline reading, with potential for future backends (local, sync, server).

## Architecture

### Current State

```
Monorepo (npm workspaces + Turborepo)
│
├── apps/web          → Vite 7 + React 19 PWA
│   ├── src/sw.ts      → Service worker (precaches app shell)
│   ├── vitest.config  → Unit/component test config
│   └── uses           → @workspace/ui for components
│
└── packages/ui       → shadcn/ui component library
    └── provides      → Button, theme, utilities, CSS
```

### Planned Capabilities

- **Format support**: Markdown reader, EPUB reader, extensible to more
- **Storage**: Client-side (IndexedDB via SurrealDB or similar)
- **Plugin system**: Extensible reader pipeline
- **Knowledge graph**: Data model for notes/books interlinking

### Implemented

- **Service Worker**: Offline app shell via Workbox (injectManifest) — precaches index.html, JS, and CSS; three-tier routing (SPA redirect → validation → 404) with shared route definitions from `route.path.ts`; cold-visit handling via `404.html` redirect
- **PWA Manifest**: Auto-generated by vite-plugin-pwa, auto-injected in HTML
- **Test Infrastructure**: Vitest + React Testing Library + jest-dom, co-located tests

## Coding Guidelines

### TypeScript

- **Strict mode** everywhere (`strict: true` in tsconfig)
- **Service workers** also typed TypeScript (compiled for target)
- **TSDoc** on all exported functions, components, and hooks
- **Comments** explain *why* for non-obvious logic, not *what*

### Modularity & Composition

- Functions over classes; composition over inheritance
- Multi-step string/state transformations → extract to utility function
- Prefer declarative pipelines over imperative chains
- When a library cleanly replaces boilerplate, consider using it during planning.

### UI (shadcn/ui Conventions)

- Use `cn()` for conditional class merging (from `clsx` + `tailwind-merge`)
- Semantic color tokens only — no raw `bg-blue-500` or `dark:` overrides
- Layout via `flex gap-*`, never `space-x-*` / `space-y-*`
- Forms use `FieldGroup` + `Field` components
- See `.agents/skills/shadcn/rules/` for full conventions

## Development Workflow

### Commands

| Command | Description |
|---------|-------------|
| `npm run dev` | Start all dev servers |
| `npm run build` | Build all packages |
| `npm run lint` | Lint all packages |
| `npm run format` | Format with Prettier |
| `npm run typecheck` | Type-check all packages |
| `cd apps/web && npm run test` | Run Vitest in watch mode |
| `cd apps/web && npm run test:run` | Run Vitest once (CI) |

### OpenSpec Workflow

Changes are managed via OpenSpec:

1. **Propose**: `/opsx:propose <change-name>` — creates proposal, design, tasks
2. **Apply**: `/opsx:apply <change-name>` — implements tasks incrementally
3. **Verify**: `/opsx:verify <change-name>` — validates implementation
4. **Archive**: `/opsx:archive <change-name>` — finalizes completed change

Artifacts live in `openspec/changes/<change-name>/`. Main specs in `openspec/specs/`.

### Agent Docs Convention

```
AGENTS.md  →  Instructions for AI coding agents + codemap
```
